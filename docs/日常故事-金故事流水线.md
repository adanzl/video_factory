# 日常故事 · 金故事流水线

> 更新日期：2026-08-21。  
> 目的：**全自动**「站外素材 → 金故事（多为第三方叙述）
> → 对话化骨架 → 注入 D2 → 闭环升降」。  
> **零人工**；单位是 **金故事**，不是金句。  
> **v0 采集范围仅 B 站**；抖音暂不做。  
> 与主流水线见 [日常故事.md](./日常故事.md)；  
> 五类矛盾见 [日常故事-类型.md](./日常故事-类型.md)。

---

## 1. 要解决什么

D1→D2 靠抽象线路 + humor 检测器逼近「好笑」，稳定度不够。
站外素材多数是 **UP 主讲解、家长复述、合集旁白**——第三方视角讲
一件趣事，不是现成的昭昭/灿灿对白。

本流水线：

1. 从 **B 站** 采集 **完整微型故事**（起承转合），不抽孤立「好笑一句」；
2. LLM 结构化：**机制 M + 结构类型 + beat**；
3. **对话化**（H3b）：把第三方叙述转成 **对话骨架**（speaker + 意图，
   非定稿台词）；
4. 按主题检索，把 **故事 beat + 对话方向** 注入 D2，由现有 D2 写成
   合格对白；
5. **quality + 防抄 gate** 自动升降金故事库。

边界：

- 库存的是 **故事结构与对话方向**，不是站外原文或定稿台词；
- 禁止整段照抄叙述 / 骨架（`provenance_gate` + 金故事原文归一化）；
- 「好笑」用传播指标 + LLM 故事质量分 + 注入后 humor 分代理。

## 2. 原料形态（为何不是金句）

| 来源形态 | 典型样子 | 流水线取什么 |
| --- | --- | --- |
| 第三方讲解 | 「有个妹妹占着酱碗不让哥哥吃，妈妈一问…」 | 整段 **story_raw** |
| 家长热评复述 | 「我家娃原话：…然后我说…」 | 去壳后的 **情节链** |
| 混剪旁白 + 插话 | 旁白为主，偶尔引号 | 合并为 **一条金故事** |
| 纯对白视频（少） | 姐弟原声对话 | 仍走 **故事抽取**，不单独存金句 |

**原则**：入库最小单位 = **一件能讲清冲突与收束的微型故事**；
单句只作为故事中的一拍，不单独成库条目。

## 3. 在总流水线中的位置

```text
【现有】
D1 →（D1.5）→ D2 正文（昭昭/灿灿 对白）→ D2b → 质检

【金故事侧路 · 全自动】
H0 采集（B 站 search + 元数据/热评）
  → H0b 逐字稿（yt-dlp · faster-whisper）
  → H1 规则初筛
  → H2 故事原料抽取（逐字稿 + 热评 → story_raw）
  → H3 故事结构化（M + A–E + beat + theme_family）
  → H3b 对话化骨架（第三方 → 昭昭/灿灿 speaker 意图）
  → H4 入库（SQLite `gold_story` 表）
       ↓
  H5 检索（theme + story_type）
       ↓
  H6 注入块模板化
       ↓
  H7 注入 D2 user（故事 beat + 对话方向，非原文）
       ↓
  H8 现有质检
       ↓
  H9 统计回写（promoted / retired）
```

注入点：**D2 user 拼装前**（H7 / D1.8）。D2 仍负责写出最终对白；
金故事只提供 **该怎么好笑地推进**，不替代 D2。

## 5. H0 自动采集

### 5.1 B 站（主通道）

**cron** 每日/每周；关键词轮换：

| 词 | 用途 |
| --- | --- |
| 姐弟吵架 / 兄妹抢 / 兄妹日常 抢 | 争物故事 |
| 二胎抢东西 | 占有型 |
| 童言无忌 / 萌娃语录 / 萌娃名场面 | 讲解类合集（第三方叙述多） |

**API 链（H0）**：search → view → reply（长评优先）。

**逐字稿（H0b）**：对通过 H1 的 BV 批量转写，见 §5.4。  
**不**依赖 bili2text vendor；下载与 ASR 在本项目 `gold_story/` 内实现。

**H1 初筛**：播放/评论阈值同前；排除外语、育儿课、游戏 IP；
标题偏 **名场面 / 合集 / 日常 / 抢 / 吵架** 优先（更易含完整故事）。

### 5.4 逐字稿（H0b · yt-dlp + faster-whisper）

站外视频多数 **无 CC**；H0b 在本项目内完成 **下载 → 抽音频 →
faster-whisper**，不内嵌 bili2text，便于后续接抖音等同构扩展。

#### 目录

```text
backend/app/services/daily_story/gold_story/
  download.py      # 按 source 下载（v0: bili；预留 douyin）
  whisper.py       # faster-whisper ASR
  transcript.py    # batch 入口
backend/scripts/gold_story_transcript.py
data/gold_story/transcripts/        # 逐字稿 {source_id}.txt
data/gold_story/media_workspace/    # 临时音视频（不进 git）
```

#### 分层

| 层 | 职责 | v0 | 后续 |
| --- | --- | --- | --- |
| 下载 | `download_media(ref)` | `source=bili`，yt-dlp + cookie | `source=douyin` |
| ASR | `whisper.transcribe_audio` | CPU int8（默认） | ROCm GPU |
| 编排 | `transcribe_media` / `batch_*` | `batch_bilibili` | 多平台 batch |

抖音 **H0 采集**仍不在 v0；H0b 接口已按 `source` + `source_id` 设计。

#### 依赖

| 项 | 说明 |
| --- | --- |
| 下载 | **yt-dlp** + `ffmpeg` |
| ASR | **faster-whisper**，读 `/mnt/data/whisper/{base\|medium}/` |
| Cookie | B 站：`BILI_COOKIE_PATH`；抖音：`DOUYIN_COOKIE_PATH`（后续） |

**环境变量**（`.env`）：

```bash
WHISPER_MODEL_DIR=/mnt/data/whisper
GOLD_STORY_WHISPER_MODEL=base
GOLD_STORY_WHISPER_DEVICE=cpu
GOLD_STORY_WHISPER_COMPUTE_TYPE=int8
GOLD_STORY_MEDIA_WORKSPACE=data/gold_story/media_workspace
# GOLD_STORY_USE_PROXY=false
```

#### mini ROCm GPU（780M · gfx1103）

mini 为 **AMD 780M 集显**，无 NVIDIA CUDA。PyPI 的 `ctranslate2`
为 CUDA-only；要用 GPU 须改装 **ROCm wheel**（已解压示例路径）：

```text
/mnt/data/whisper/rocm-python-wheels-Linux-whl/*.whl
```

`.env` 改为 GPU（ROCm 下 device 仍写 `cuda`）：

```bash
GOLD_STORY_WHISPER_DEVICE=cuda
GOLD_STORY_WHISPER_COMPUTE_TYPE=float16
```

**系统环境变量**（780M 实测必需；cron / systemd 须 `export`）：

```bash
export HSA_OVERRIDE_GFX_VERSION=11.0.0
export CT2_CUDA_ALLOCATOR=cub_caching
```

缺上述变量时，GPU 推理可能 **segfault**；`get_cuda_device_count()`
仍可能为 1。OEM 内核 + `/dev/kfd` 等栈说明见 `docs/SD15部署.md`。

**速度参考**（3 分钟旁白，`data/media/30`，2026-08-22）：

| 模型 | 配置 | 转写耗时 | 实时倍率 |
| --- | --- | --- | --- |
| base | CPU int8 | 8.6s | 21x |
| base | GPU float16 | 6.3s | 28x |
| medium | CPU int8 | 159s | 1.1x |
| medium | GPU float16 | 140s | 1.3x |

- `base`：CPU 已够快（3 分钟 ≈ **9s**），GPU 约 **1.36x**
- `medium`：CPU/GPU 均 **略快于实时**（3 分钟 ≈ **2.5–3min**），
  GPU 仅 **1.14x**；batch 慎用，cron 默认 **CPU + base**

#### 服务器模型（mini · `/mnt/data/whisper`）

| 路径 | 引擎 | 大小 | 用途 |
| --- | --- | --- | --- |
| `base/`（含 `model.bin`） | faster-whisper | 139M | **cron 默认** |
| `medium/`（含 `model.bin`） | faster-whisper | 1.5G | 更准，batch 慎用 |
| `*.pt` | openai-whisper | — | 不用 |

`WhisperModel(f"{WHISPER_MODEL_DIR}/{model}")`，`model` 为目录名；  
禁止联网自动下载，须预置在 mini。

#### B 站下载注意

- 412 / SSL：默认 **直连**（`GOLD_STORY_USE_PROXY=false`）
- Cookie：与投稿共用 `BILI_COOKIE_PATH`，传给 yt-dlp `cookiefile`

**转写失败**：降级 H0 热评/简介，不阻塞主链。

### 5.2 抖音（暂不做）

v0 **不实现**抖音 **H0 采集**：风控与接口不稳定。

### 5.3 传播分

`engagement_score` 用于排序与 tie-break，不单独决定入库。

## 6. H2 故事原料抽取

目标：从文本中得到 **一段可独立理解的第三方叙述**（80–400 字），
含冲突、升级、落点。

| 优先级 | 来源 | 策略 |
| --- | --- | --- |
| 1 | H0b 逐字稿 | yt-dlp + faster-whisper 全文 |
| 2 | 长热评 / 简介 | 完整复述帖；与逐字稿互补 |
| 3 | 短评拼接 | 仅当同一楼内多段可连成情节 |

对优先级 1–2 合并后，**LLM 切段**：从旁白/复述中选出 **一条** 微型故事
（合集常含多梗，只取一条）。

**LLM 输出（H2）**：

```json
{
  "story_raw": "第三方叙述全文…",
  "perspective": "third_person | mixed | direct_dialogue",
  "has_complete_arc": true,
  "extract_confidence": 0.0
}
```

`has_complete_arc=false` 或 confidence < 0.5 → 丢弃。

**不产出** `quote` 字段；叙述里的引号对白保留在 `story_raw` 内，
供 H3/H3b 解析。

## 7. H3 故事结构化

**模型**：Flash；输入 `story_raw` + 视频标题。

```json
{
  "title": "酱碗争夺战",
  "conflict_core": "妹妹占酱碗不让哥哥，被问理由",
  "funny_why": "自私包装成公平",
  "mechanism": "M2",
  "structure_type": "C",
  "theme_family": "占有整件物",
  "beat": [
    "占有不让",
    "被质问",
    "歪理自洽",
    "嘴硬不收"
  ],
  "banned_literals": ["妹妹", "哥哥"],
  "structure_mapping_note": "站外酱碗→站内可换为酸奶/抱枕等，勿写入 banned"
}
```

`banned_literals` **仅**站外真名、须 remap 称谓；**禁止**场景词（画画）、
可拍细节（碘伏）、meta（朋友圈）。入库前 `sanitize_banned_literals` 过滤。

约束：`mechanism` ∈ §9.2；`structure_type` ∈ §9.3；beat 4–6 步；
**禁止**把 `story_raw` 原文贴进 beat。

## 8. H3b 对话化骨架（第三方 → 昭昭/灿灿）

**目的**：站外是「有人讲事」，D2 要「姐弟对白」。本步产出
**对话种子**，不是定稿。

**模型**：Flash；输入 H3 JSON + `story_raw` + 任务角色表
（昭昭 7 岁弟 / 灿灿 10 岁姐 / 妈妈少出场）。

```json
{
  "setting": "餐桌旁，酱碗…",
  "dialogue_seed": [
    {"speaker": "昭昭", "intent": "想要分酱，被挡"},
    {"speaker": "灿灿", "intent": "占着不让，称自己已经占住了"},
    {"speaker": "昭昭", "intent": "质问凭什么"},
    {"speaker": "灿灿", "intent": "歪理：你刚才吃多了所以现在我要多吃"},
    {"speaker": "昭昭", "intent": "嘴硬不服，扣公平规则"}
  ],
  "closing_intent": "C 类回旋镖 + 末句嘴硬",
  "dialogue_confidence": 0.0
}
```

规则：

- `dialogue_seed` 用 **intent**，不用成品台词；
- 爸妈在源故事里 → 映射为 **灿灿/昭昭** 或 **妈妈**（E 类），
  LLM 须写进 `speaker_map_note`；
- 禁止与 `banned_literals` 同词写 intent（促 D2 换物换说法）。

### 8.1 gold_chat 扩写（独立流程）

H3a/H3b 产出 **契约 + seed**；`gold_chat_convert` 扩成成品对白。
代码：`gold_chat_fidelity.py` + `gold_chat_convert.py`。

#### 三层保真（顺序）

1. **H3a beat_chain**：按类型写清拍点（H 须 6–8 拍，M5+H 须双向互毁）
2. **H3b dialogue_seed**：每拍 1–3 条 intent，M5+H 禁合并「问谁先动手」与「都错了」
3. **gold_chat checklist**：按 `mechanism+structure_type` 注入扩写链，对照
   `payload.beat` / `closing_intent` / `story_raw`

#### M5+H 扩写链（不可跳步）

升级 → 双向互毁 → 伤情 → 哭腔道歉 → M5 拒和 → M5 加码（妈妈介入前）
→ 妈妈问谁先动手 → 定责劝和 → 仪式性和好 → 齐声不打了 → 碘伏/收场

**禁止 Invent**：story_raw 未出现的彩虹/交换/拉钩等暖收。

**banned_literals**：仅 remap 真名/称谓；场景词（画画/碘伏/朋友圈）不禁。
入库前 `sanitize_banned_literals` 过滤 LLM 误伤。

## 9. 结构类型与机制

### 9.1 结构类型 A–E

管 validate 收束；金故事 **不覆盖** 任务已定的 `story_type`。
检索时 `structure_type` 须与任务一致。

### 9.2 机制 M1–M12

| 代码 | 名称 |
| --- | --- |
| M1 | 回旋镖扣原话 |
| M2 | 自私包装公平 |
| M3 | Threat 互升级 |
| M4 | 递台词 |
| M5 | 拒和加码 |
| M6 | 成人概念童化 |
| M7 | 字面执行跑偏 |
| M8 | 一锤可拍 |
| M9 | 结盟甩锅 |
| M10 | 假帮腔讽刺 |
| M11 | 灵魂拷问 |
| M12 | 家长旁观 |

H3 输出 `mechanism` ∈ 上表；入库列 `mechanism` 存 M 码。

### 9.3 结构类型 A–E（与日常故事对齐）

与 [日常故事-类型.md](./日常故事-类型.md) §3 一致；H3 另输出
`structure_type`（单字母）。代码：
`gold_story/types.py`（`normalize_structure_type`）。

| 代码 | 名称 | 公式 | 收束 |
| --- | --- | --- | --- |
| A | 权威翻车 | 立规→一锤可拍→埋句→反噬 | 末四拍 |
| B | 结盟翻车 | 结盟→走样→甩锅→露馅 | 露馅后仍嘴硬 |
| C | 公平执念 | 争同一资源→双规则→回旋镖 | 被戳穿方末句嘴硬 |
| D | 字面执行 | 合理规矩→歪读执行→跑偏 | 执行方回旋镖 |
| E | 妈妈破功 | 妈妈立论→追问→改口→闭环 | 妈妈破功 |

**M 与 A–E 常见映射**（检索时 `structure_type` 须与任务一致）：

| mechanism | 常见 structure_type |
| --- | --- |
| M1 | C / D / A |
| M2 | C |
| M4 | G（嘴硬心软；争物/双规则改 M1/M2→C） |
| M5 | A（拒和加码）；第三方调解收束可标 H；否决压住可标 J |
| M6 | A / E |
| M7 | D |
| M8 | A（有反噬）；镇住不翻车可标 J |
| M9 | B |
| M10 | E |
| M11 | I |
| M12 | K |

### 9.4 F–K 扩展类型

| 代码 | 名称 | 状态 |
| --- | --- | --- |
| F | Threat 互升级 | 金故事已标；不入 A–E 任务注入 |
| G | 嘴硬心软 | M4 默认映射 G；gold_story/gold_chat 已用 |
| H | 第三方化解 | M5 可选；gold_story/gold_chat 已用；暂不入 H5 注入 |
| I | 问倒收束 | M11 默认映射 I；gold_story/gold_chat 已用；暂不入 H5 注入 |
| J | 权威压住 | M8/M5 可选；gold_story/gold_chat 已用；暂不入 H5 注入 |

## 10. 落库设计（SQLite）

**原则**：采集到的金故事 **必须写入 `data/data.db`**，与 `daily_story`
（待拍剧本）分表。逐字稿全文过大，**只存磁盘路径**；结构化字段 +
`payload_json` 进库。

### 10.1 与 `daily_story` 的区别

| 表 | 用途 |
| --- | --- |
| `gold_story` | 站外参考：story_raw、beat、dialogue_seed、注入统计 |
| `daily_story` | 站内成片剧本：D2 产出、可建 job、可投稿 |

一条 `daily_story` 生成时可 **引用** `gold_story_id`（job meta 或
注入日志），但两表不合并。

### 10.2 表结构（`gold_story`）

```sql
CREATE TABLE IF NOT EXISTS gold_story (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    source TEXT NOT NULL,
    source_id TEXT NOT NULL,
    url TEXT NOT NULL,
    status TEXT NOT NULL DEFAULT 'active',
    mechanism TEXT NOT NULL,
    structure_type TEXT NOT NULL,
    theme_family TEXT,
    title TEXT,
    conflict_core TEXT,
    auto_score REAL NOT NULL,
    engagement_score REAL,
    content_hash TEXT NOT NULL,
    times_used INTEGER NOT NULL DEFAULT 0,
    avg_humor_delta REAL,
    copy_hits INTEGER NOT NULL DEFAULT 0,
    transcript_backend TEXT,
    transcript_path TEXT,
    payload_json TEXT NOT NULL,
    created_at TEXT NOT NULL DEFAULT (datetime('now')),
    updated_at TEXT NOT NULL DEFAULT (datetime('now')),
    last_used_at TEXT
);

CREATE UNIQUE INDEX IF NOT EXISTS idx_gold_story_source
    ON gold_story(source, source_id);
CREATE INDEX IF NOT EXISTS idx_gold_story_pick
    ON gold_story(status, structure_type, mechanism);
```

### 10.6 去重与入库门槛

1. `(source, source_id)` 唯一：同一 BV **只保留一条**金故事；更新走
   `UPDATE payload_json` + `updated_at`。
2. `content_hash`：`normalize(story_raw)` 后 hash；与已有行相同则 skip。
3. 近重复：压缩 `story_raw` 后最长公共子串 ≥16 则 skip
   （转载换 BV、抽稿措辞不同仍能挡住）。
4. `auto_score ≥ 0.55` → `status=active`；否则 **不写库**。

**auto_score**：

```text
0.25·engagement_norm
+ 0.25·extract_confidence
+ 0.25·structure_confidence
+ 0.25·dialogue_confidence
```

## 17. 可持续性分析

> 回答：金故事库 **能否长期跑下去**，而不是一次性实验。

### 17.1 结论摘要

| 维度 | 判断 | 一句话 |
| --- | --- | --- |
| 内容供给 | 🟢 可持续 | B 站萌娃/姐弟内容持续产出，可 cron 补库 |
| 库内质量 | 🟢 可持续 | H9 升降 + 容量上限，差故事会自我淘汰 |
| 技术依赖 | 🟡 需维护 | B 站 search API + 转写工具版本；有热评降级 |
| 边际成本 | 🟢 可控 | faster-whisper 本地 CPU，无转写 API 费 |
| 创意新鲜度 | 🟢 可持续 | 外部故事 + D2 重写，比静态正例不易枯竭 |
| 合规 | 🟡 低风险 | 只存 beat/intent、禁原文照抄，仍须防抄 gate |

**整体**：适合作为 **长期侧路** 运行；主链不依赖它，失败了可整链关闭。

---

### 17.2 内容供给（会不会采秃）

#### 有利因素

- 萌娃/姐弟/名场面类 UGC 在 B 站 **持续上新**，非一次性语料；
- 入库单位是 **故事类型**（C 公平执念…），同一视频可只取一条，
  换主题后 D2 仍可再生；
- 与现有 `_THEME_OVERUSED_BAN`、DB 已出题 **可联动去重**，
  避免同一故事梗反复注入。

#### 风险与对策

| 风险 | 对策 |
| --- | --- |
| 合集视频 **重复讲述** 同一梗 | `story_raw` 归一化 hash；相似度 > 阈值则 skip |
| 关键词搜到的 **头部梗** 过窄 | 搜索词轮换 + `theme_family` 分散检索 |
| 第三方叙述 **质量参差** | `extract_confidence` + auto_score 门槛；宁缺勿滥 |
| 与站内已发稿 **撞梗** | H5 检索时排除近期 job 的 `conflict_core` 近义 |

**预期**：cron 日产 10–30 条候选、入库 2–5 条 **可长期维持**；
库稳定在每 structure_type 数十条 promoted + active，靠 H9 滚动。

---

### 17.3 库内生态（会不会越用越烂）

```text
入库(active) → 注入 → humor_delta 回写
  → promoted（好用）/ retired（差或易抄）
  → 每 structure_type cap 30 active，低分淘汰
```

- **promoted** 条目形成「经线上验证」的核心池，不随 cap 淘汰；
- **retired** 防止差故事占检索位；
- 无匹配或库空 → **不注入**，行为与现网一致，零回归风险；
- 若长期 humor_delta 全负：库会缩到很小，**自动失效但不拖垮主链**。

可持续条件：开启 `GOLD_STORY_AB` 或 job meta 记录 delta，
否则 H9 无法闭环，库会退化为静态池。

---

### 17.4 技术与运维（会不会突然挂）

| 依赖 | 稳定性 | 降级 |
| --- | --- | --- |
| B 站 search/view/reply API | 非官方；偶发 412 | 请求间隔；可选 Cookie；失败跳过当次 cron |
| yt-dlp + faster-whisper | B 站/抖音下载偶发失败 | Cookie 更新；仍失败则热评 |
| LLM H2/H3/H3b | 稳定 | 候选丢弃率可调；降 `--max` |

**运维量**：每日 cron + 每周 feedback，**无需人审**；
异常看日志与 `active` 入库数即可（如连续 7 天入库 0 → 告警）。

---

### 17.5 成本（能不能一直开）

金故事链 **在 D2 之外**，边际成本主要在采集 cron（非每条成片）：

| 环节 | 粗算（单条入库成功） |
| --- | --- |
| H0b 逐字稿 | faster-whisper CPU，无 API 费 |
| H2 抽故事 | 1× Flash |
| H3 结构化 | 1× Flash |
| H3b 对话 seed | 1× Flash |

若每日转写 20 条候选、入库 5 条：约 **15 次 Flash/日** +
本地转写算力（与成片 TTS/出图并行时需限流）。
若 humor 提升减少 D2 重试，**有机会净节省**（需 M2 实测）。

建议：`GOLD_STORY_CRON_MAX`、逐字稿结果磁盘缓存、低 engagement 跳过 H0b，
见 [成本.md](./成本.md) 配额思路。

---

### 17.6 创意与产品（会不会越做越像搬运）

- 注入的是 **beat + intent**，D2 仍按 A–E 写昭昭/灿灿 口语，
  成品是 **改写** 而非复述站外视频；
- `banned_literals` + provenance 降低「梗感重合」；
- 机制层 M1–M10 抽象，同一 M2 可映射抱枕/酸奶/遥控器，
  **比 line.py 静态正例更不易写枯**。

风险：若检索总命中同一 mechanism，成片节奏会单調。
对策：H5 对「近 3 job 同 mechanism」降权（文档 §11 已写）。

---

### 17.7 合规与版权（长期隐患）

- 不存储、不注入 **定稿对白**；`story_raw` 仅本地库、不进 git；
- 生成阶段禁照抄原文与 seed 字面；
- 站外材料作 **结构参考**，与现有「正例只学槽位」同一原则。

残余风险：极高相似度的 **情节** 仍可能引发观感问题；
靠 humor/多样性 + 不追热点单条梗 缓解。抖音暂不做也减一条
合规不确定通道。

### 17.8 与现有方案对比（值不值得并行）

| | line.py 静态正例 | 金故事库 |
| --- | --- | --- |
| 新鲜度 | 写死，易枯竭 | 外源持续补 |
| 维护 | 改 prompt + provenance 扩列表 | cron + H9 自维护 |
| 风险 | 模型照抄正例（已防） | 照抄 story_raw（需扩 gate） |
| 依赖 | 无 | yt-dlp + faster-whisper + LLM |

建议 **并行**：金故事 **增强** D2，不 **替换** A–E 线路与 validate。
开关：`GOLD_STORY_ENABLED=0` 可一键回退现网行为。

### 17.9 建议监控指标（可持续性仪表盘）

| 指标 | 健康区间 | 异常时 |
| --- | --- | --- |
| 周入库 active 数 | ≥5 | 查 API / 初筛 / LLM |
| promoted 占比 | 10%–40% | 过低→注入无效；过高→库太小 |

| copy_hits 率 | 低 | 加强 provenance / banned_literals |

```text
L1 视频候选（H0/H1）
  → L2 故事原料（H2）
  → L3 结构与机制（H3/H3b）
  → L4 入库门禁（H4）
  → L5 注入匹配 + 线上升降（H5/H9）
```

#### L1 视频候选：搜什么、留什么

| 留 | 丢 |
| --- | --- |
| 标题含 姐弟/兄妹/抢/吵架/名场面/日常/语录 | 育儿课、教科书、外国娃、游戏 IP |
| 播放 ≥10 万，或 评论 ≥50 | 纯音乐、无对话合集 |
| 热评有 **整段复述**（然后/最后） | 只有观众玩梗、无情节 |

搜索词轮换（与专家对话一致）：萌娃吵架、童言无忌、二胎日常、
姐弟抢东西、萌娃讲道理、萌娃名场面。

#### L2 故事原料：从逐字稿里抽什么

**要**：一件 **微型故事**（80–400 字），含：

1. **起**：争物 / 立规 / 结盟（可拍实物）  
2. **承**：升级或歪读（加赛、歪理、Threat 链）  
3. **转**：被质问 / 戳穿 / 教递台词  
4. **合**：嘴硬 / 回旋镖 / 露馅（能映射 A–E 收束）

**不要**：

- 孤立的「好笑一句」（再亮也 discard）  
- 纯家长说教、无孩子行动  
- 只有情绪（哭喊「还我」）无 **规则或歪理**（须配完整 A–E 链才入库）

`extract_confidence < 0.5` → 不进入 L3。

#### L3 结构与机制：能不能进昭昭/灿灿流水线

LLM 结构化时按 **双门槛**：

| 门槛 | 判定 |
| --- | --- |
| **机制** | 必须命中 §9.2 M1–M10 之一，且 `funny_why` 一句话说清 |
| **收束** | `structure_type` ∈ §9.3；映射牵强写 note，note 多者降权 |
| **可迁移** | 爸妈/兄妹源 → 有 `speaker_map_note`；无法映射则 discard |
| **theme_family** | 占有 / 消耗 / 操作 / 结盟 … 便于 H5 检索 |

专家对话沉淀的 **高频好机制**（优先补库）：

| 机制 | 站外例 | 站内用途 |
| --- | --- | --- |
| M2 自私包装公平 | 酱碗「我多吃因你吃多了」 | C 类占有战 |
| M4 递台词 | 骂完护短 / 递台词 escalation | G 类嘴硬心软 |
| M5 拒和加码 | 「我不接受你的道歉」 | A 末段 / 嘴硬 |
| M6 童化歪理 | 元宝式灵魂拷问 | A/E 追问链 |
| M1 回旋镖 | 规则扣原话 | C/D/A 收束 |

#### L4 入库门禁：写入 `gold_story` 表

同时满足才 `INSERT`：

```text
auto_score ≥ 0.55
content_hash 不重复
(source, source_id) 不重复
structure_confidence ≥ 0.6 且 dialogue_confidence ≥ 0.6
```

`auto_score` 权重（与 §10.6 一致）：

```text
0.25·engagement_norm + 0.25·extract
+ 0.25·structure + 0.25·dialogue
```

宁缺勿滥：候选 20 条入库 2–5 条 **正常**。

#### L5 注入与淘汰：库内再选稿

**注入（H5）** 不是「库里有就用」：

1. `structure_type` **必须**等于任务 `story_type`  
2. `theme_family` 与本次 `theme` 关键词 overlap  
3. `promoted` > `active` > 其余  
4. 近 3 篇 job 同 `mechanism` **降权**（防节奏单調）  
5. 无匹配 → **不注入**（D2 走原线路）

**淘汰（H9）** = 线上选稿反馈：

| 信号 | 动作 |
| --- | --- |
| `times_used ≥ 3` 且 `humor_delta ≥ +2` | `promoted` |
| `copy_hits ≥ 2` 或 `humor_delta ≤ -3` | `retired` |
| 90 天 `times_used = 0` | `retired` |

#### 选稿口诀（专家对话摘要）

1. **选故事，不选句**——没有起承转合不入库。  
2. **选机制，不选原词**——M 层抽象，台词 D2 重写。  
3. **选能迁，不选原 speaker**——迁不进昭昭/灿灿就丢。  
4. **选能收束，不选纯段子**——必须落进 A–E 之一。  
5. **传播只海选，好笑靠 delta**——播放量帮找候选，promoted 靠成片。

#### 与 §17.2 的关系

§17.2 管 **供给侧会不会枯竭**；本节管 **单条怎么留、怎么扔**。
补库 cron 按 L1→L4 执行；成片任务按 L5 执行。
