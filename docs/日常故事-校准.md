## 2. 校准工作流（换机器继续时照做）

1. **跑样**：

   ```bash
   cd backend
   conda run -n flask_env python \
     backend/scripts/preview_daily_story_batch.py \
     --story-type X --themes "主题1" "主题2" \
     --parallel 2 --out tmp/daily_x_baseline.json
   ```

   输出会打印：字符数 / 句数 / speaker 分布 / 开场 / 头尾句 / 妈妈句 /
   `quality`（grade + score + summary）与 punchline。结果 JSON 存 `tmp/`
   （已 gitignore），不提交。
2. **判定缺口**：对照各类型叙事契约（`docs/日常故事-类型.md` §3）
   与硬卡 / 观感输出，区分三类问题：
   - 生成总不达标 → 改 `line.py` 提示词或重试 hint；
   - 机读不变量漏判 → 改 `validate.py`（结构槽位，勿按主题词穷举）；
   - 写得不好但不违规 → 观感降分或改 `line.py`，不做生成硬拦。
3. **防回归**：每次改动给 `backend/tests/` 加单测（纯函数可测的部分），
   参考 `test_llm_script_title.py` 对 A 类角色自称的测试写法。
4. **收尾**：某类达标后置 `quality_ready=True`（如已开则确认）、
   有 D1.5 需要时再开 `story_plan.ENABLED`，并更新 §1 表与本节。

## 4. 红线与分工

- **三层分工**（`.cursor/rules/daily-story-validate.mdc`）：
  - 叙事与措辞 → `line.py` / `prompts.py` / 重试 hint；
  - 机读不变量 → `validate.py`（字数、speaker、末段结构槽位）；
  - 观感 → `quality.py`（类型 pattern，不按单篇主题加 regex）。
- **validate / patch 允许**：与类型契约对齐的抽象不变量、可程序判定且
  全类型通用的规则；**禁止**：单篇 / 单主题台词词表、regex 穷举
  「好/坏措辞」、把观感扣分问题做成生成硬拦。
- **本地修稿边界**：patch 只做类型级结构修补，禁按主题关键词分支改写
  台词；内容类硬卡不过一律交 LLM 重试。
