# 文生图提示词槽位化方案

> 2026-08-20。范围：daily_story / chat 流水线的文生图（T2I）提示词生成。
> 背景：`docs/提示词构建.md` 的 A3 链路。本方案替换原「多来源文本拼接 + regex
> 清洗」的实现，解决提示词自相矛盾问题（详见后文）。
> 相关：`docs/日常故事.md`、`docs/日常故事-校准.md`。

---

## 0. 问题与目标

旧实现把 LLM 的 `visual_brief`、分镜1场景锚点、家具补回、各类硬锁按顺序拼接，
冲突清洗只作用于拼接前的 `visual_brief`，后注入的内容（场景锚点、家具、硬锁）
从不做冲突仲裁，regex 补丁打地鼠，产出频繁自相矛盾。实测（job 80）：

- 「沙发和茶几上没有任何物品」与「茶几上放着遥控器和空水杯」并存
- 「茶几上放着遥控器和空水杯画面中有茶几」重复且粘连（句号被 strip）
- 「昭昭龇牙咧嘴使劲」与口型锁「昭昭嘴巴自然闭合」矛盾
- LLM 动作描写与硬锁动作描写双重存在且不一致
- 清洗残留无主语断句（「眼睛眯成缝。」）

目标：矛盾在**结构层**就不该产生，而非事后抓。

---

## 1. 核心原则

1. **单一负责人**：每类信息只有一个槽位产出，其它环节禁写
2. **清洗内聚**：scrub 只在槽位内部（产出方保证自己干净），禁止跨槽位 regex 互改
3. **拼装零智能**：拼装器只 join，不做任何判断
4. **审核独立于生成**：L1 结构审核（代码）+ L2 语义审核（LLM reviewer）

---

## 2. 架构总览

```text
分镜脚本（dialogue + visual_brief + object_states 结构化字段）
  → 状态机层（道具状态快照：跨镜继承 + 变更事件校验）
  → 槽位渲染层（代码，零判断只 join）
  → 审核层（L1 代码全量 + L2 LLM 可选档位）
  → 出图 → 出图质检（现有）
```

---

## 3. 槽位定义总表

| # | 槽位 | 负责环节 | 字数 | 内容 | 禁写 |
| --- | --- | --- | --- | --- | --- |
| S1 | 风格 | 常量 | ~30 | 涂鸦画风定调，全片唯一 | 光照、具体场景 |
| S2 | 场景锚点 | code（模板，按 setting） | 10-20 | 地点 + 硬锚点名词 | 小物件、材质 |
| S3 | 角色外貌 | 常量（子块拼装） | ~86/2人 | 外貌基块 + 身高锁 + 发色锁 + 地垫变体 | 道具状态 |
| S4 | 本镜画面 | **LLM（唯一入口）→ JSON** | ≤80 | 谁/动作/表情 | 场景、外貌、风格、数量、口型 |
| S5 | 道具状态 | **code 状态机** | ~60 | 物品数量/位置/持有人/形态 | 人物动作 |
| S6 | 口型锁 | code（dialogue 推导） | ~30 | 谁说话谁闭嘴 | — |
| S7+8 | 镜头参数 | code（shot_type+cast+staging） | ~70 | 景别/站位/光照 | — |

删除：句首锚点、句末重申、人数锁重复段、fixed_furniture 补回（并入 S2/S5）。
总预算 ~350 字。

## 4. 常量压缩（S1/S2/S3，已过 Agnes 评审）

### S1 风格（45→30字）

```text
儿童情绪涂鸦风，彩铅蜡笔混合笔触，高饱和色彩，涂色出界，手工感。
```

删「线条用力不均」「橡皮擦拭痕迹」（后者降级为可选，画风过干净时加回）。

### S2 场景锚点（通用模板，按 setting 生成）

```text
格式：地点，硬锚点A，硬锚点B，硬锚点C（，硬锚点D）
```

- 硬锚点按**面积从大到小**排序，室内≤3、户外≤5
- 只保留**一个**辨识度形容词（"圆形""红色"）
- 小物件归 S5；**地垫/地毯例外**（地面锚点，写 S2）
- 10-20 字

| 场景 | 成品 |
| --- | --- |
| 客厅 | `客厅，圆形地垫，沙发，茶几。` |
| 厨房 | `厨房，水槽，餐桌，窗户。` |
| 户外 | `小区公园，滑梯，沙坑，长椅。` |

### S3 角色外貌（子块拼装）

| 子块 | 成品 | 字数 |
| --- | --- | --- |
| 昭昭基块 | 昭昭：7岁男孩，黑色超短发露耳露后颈，圆脸，蓝色短袖T恤深蓝色短裤，蓝白运动鞋。 | 37 |
| 灿灿基块 | 灿灿：10岁女孩，黑色单侧高马尾，粉色卫衣蓝色长裤，粉红运动鞋。 | 30 |
| 身高锁 | 昭昭比灿灿矮约半个头。 | 11 |
| 发色锁 | 灿灿头发通体纯黑。 | 8 |
| 地垫变体 | 灿灿鞋→`赤脚仅穿白袜子`；昭昭→`双脚均已穿好一双蓝白运动鞋` | 按需替换 |

## 5. S4 本镜画面（LLM → JSON → 模板渲染）

LLM 不写自由文本，输出结构化 JSON：

```json
{
  "subjects": [
    {"id": "zhaozhao", "action": "双手拉紧鞋带", "expression": "皱眉抿嘴", "posture": "身体前倾"},
    {"id": "cancan", "action": "站在一旁看", "expression": "微笑", "posture": "双手背在身后"}
  ]
}
```

代码模板渲染：
`昭昭双手拉紧鞋带，皱眉抿嘴，身体前倾；灿灿站在一旁看，微笑，双手背在身后。`

防越权：JSON schema 强制 + few-shot + L1 字段级校验（出现 S2/S3/S5 实体词即裁剪/重写）。

---

## 6. S5 道具状态（状态机）

状态来源上移到分镜脚本层：

```json
{
  "shot_id": 12,
  "object_states": [
    {"object": "粉鞋", "form": "loose_knot", "holder": "none", "position": "on_mat"}
  ]
}
```

- **跨镜传递**：每镜继承上一镜状态版本，只有显式"状态变更事件"才允许改
- **状态机校验**：转移合法性（散开→打结→被拎起 ✓；打结→散开 未声明 ✗）
- **后置确认**：S5 在 S4 之后，按 S4 的物体交互确认/修正状态，不是"预言"
- 状态缺失 → 报错升级 QualityReport，不猜

## 7. S7+8 镜头参数槽

光照与构图站位合并，统一 `shot_params_deriver` 产出：景别（shot_type）、
左右站位（**需分镜脚本提供 staging/blocking 字段**）、光照（setting 室内外推导）。

## 8. 审核流程

### L1 结构审核（code，每段同步，全量）

| 检查项 | 级别 |
| --- | --- |
| 槽位字数超限 | minor |
| 冗余检测（同一实体被两次描述） | minor 自动修剪 |
| 矛盾检测（对立谓语共现：有/无、散开/打结、在手中/在垫上） | major |
| 否定词检测（不/无/没有/禁止+名词；**S1/S3 豁免**，只查 S4/S5） | major |
| 角色集合一致（S3 cast ↔ S4 subjects ↔ S7/8 站位） | major |
| 口型唯一性（S4 禁写嘴部/牙齿/笑容） | major |
| 数量一致（S4/S5 数量词 vs 状态机） | major |
| 主语完整性（禁无主语断句） | minor |
| S4 越权（出现场景/外貌/风格词） | major |
| 儿童安全规则 | major |

冲突对表**自动沉淀**：L2 每审出一个矛盾，把 (名词, 谓词对) 写回表。

### L2 语义审核（LLM reviewer，异步）

- 输入：带槽位标记的拼装结果 + 本段 dialogue + 结构化状态快照
- 不同模型/低温度 + few-shot，**只报确定矛盾**（宁少勿乱）
- 输出 JSON：`{contradictions, redundancies, unpaintable}` 注明槽位号
- 槽位级重生：S4 用其他槽位摘要+矛盾描述重写；S5/S6 先修状态机再重渲染
- 重试上限 2 次，仍失败 → `QualityReport(major, fail_stage="script")`
- 档位：仅 L1 命中 / 抽样 / 全量（控制成本）

## 9. 落地优先级

| 阶段 | 内容 | 涉及文件 | 状态 |
| --- | --- | --- | --- |
| P0 | object_states 字段；S4 JSON；S5 状态机+后置确认；S7+8 合并；S1/S2/S3 常量压缩 | script 生成、`image_prompt.py`、`visual_brief.py` | ✅ 全部完成。S4 JSON 化：daily vb 阶段 LLM 输出 `visual_subjects`（每角色 {name,posture,action,expression}）+ `object_states` + `scene_anchors`，代码模板渲染回 visual_brief（下游检测兼容），老数据无结构化字段时走自由文本兜底 |
| P1 | L1 两级检测+否定词白名单+冲突表自动沉淀；L2 reviewer+槽位级重生 | `quality/image_prompt.py`、`llm_mgr` | ✅ L1 完成（否定词/口型/对立谓词/n-gram）；L2 reviewer 完成（DeepSeek/Agnes/Mock，`IMAGE_PROMPT_L2_MODE` 控制：off/on_l1_hit/sample/full），冲突对自动沉淀 |
| P2 | 常量动态注入评估；S2 按景别裁剪；蓝裤换色决策 | `image_prompt.py` | ✅ S2 景别裁剪完成；常量动态注入不适用（T2I 无状态，跨帧一致性靠文本，见第 4 节）；蓝裤换色为内容决策，待实测定 |
| P3 | VLM 图像审核兜底；端到端微调评估 | 可选 | 📋 见下 |

### P3 结论（远期/可选，本期不写代码）

**VLM 图像审核兜底**：文本审核通过不代表图像正确。若后续接入 VLM，挂点推荐在
`image_mgr.generate_segment_images` 出图后（与现有出图质检并行），检查角色一致性
（发型/服装）、道具状态（鞋在手上/垫上）、口型。需要新增 VLM 提供方抽象与成本预算，
本期不实现。

**端到端微调评估**：素材量积累后可用高质量分镜-提示词对微调小模型直接输出完整提示词。
当前量级下收益不确定，且与槽位化架构存在方案冲突（微调=放弃槽位），建议保持槽位化
直到出现明确瓶颈再评估。
