## 1. 代码地图

```text
backend/app/services/daily_story/
  story_types/
    model.py          # StoryTypeLine、KEYWORDS、compile_layers
    __init__.py       # 注册表、parse/select、拼装辅助
    a/ c/ b/ d/ e/
      line.py         # 该类型 LLM 提示词片段（抽象线路，无场景 variant）
      validate.py     # 正文硬卡（A/B/C/D/E 已接）
      patch.py        # 本地修稿（A/C/D/E 已接）
      facts.py        # 可核对事实（A 教作业/刷牙；C 赛规/计数）
      opening.py      # 发现开场硬卡与开场分（A/B/C/D/E）
      humor.py        # 观感好笑维（A/B/C/D/E）
  prompts.py          # 共用合同、拼装入口、通用校验
  dialogue_text.py    # 单句字数上限与截断
  speaker.py          # 对白 speaker 与画面角色名对齐
  story_types/quality.py  # 观感 profile 注册与共用 scorer 构件
  a/…/quality.py        # 各类末段 scorer + QUALITY_PROFILE
  quality.py            # 日常故事观感总分（引用 story_types.quality）
```

原则：**类型差异用叙事层 + 不变量表达**，不在代码里按「刷牙/偷吃」分文件。

## 3. 五类叙事契约（抽象）

| 代码 | 名称 | 公式 | 收束 | 边界 |
| --- | --- | --- | --- | --- |
| A | 权威翻车 | 立规→一锤可拍→埋句→反噬 | 末四拍（引话/那不一样/哪里不一样/破功） | 非 C/D 主线 |
| B | 结盟翻车 | 结盟→走样→甩锅→露馅 | 露馅后仍嘴硬甩锅 | 主戏姐弟 |
| C | 公平执念 | 争同一资源→双规则→回旋镖 | 被戳穿方末句嘴硬 | 非管教权威主线 |
| D | 字面执行 | 立叮嘱→字面做→跑偏→叮嘱方破规 | 执行方用原话回旋镖 | — |
| E | 妈妈破功 | 妈妈立论→追问→改口→闭环 | 妈妈破功 | 妈妈可略多台词 |

### A 类不变量（程序与观感对齐）

1. **一锤**：中段有可画场面，事实/动作全文自洽。
2. **埋句**：灿灿前文有一句可被末段引用的原话。
3. **末四拍**：说话人顺序与功能固定（见上表）。

文档**不贴长对白正例**；回归用 `preview_daily_story_batch.py` 或线上稿。

## 4. 校准状态

| 类型 | `quality_ready` | 提示字段齐套 | 硬校验 | 本地 patch | 观感 profile |
| --- | --- | --- | --- | --- | --- |
| C | 是 | 是 | 是（`c/validate`） | 是（`c/patch`） | 是（好笑+事实+开场） |
| A | 是 | 是 | 是（`a/validate`） | 是（`a/patch`） | 是 |
| B | 是 | 是 | 是（`b/validate`） | 否 | 是（好笑+事实+开场） |
| D | 否 | 是 | 是（`d/validate`） | 是（`d/patch`） | 初版+humor/opening |
| E | 否 | 是 | 是（`e/validate`） | 是（`e/patch`） | 初版+humor/opening |

无关键词匹配时选题在 **quality_ready** 类型中随机（现为 A / B / C，
`select_story_type_tag`）。

## 5. 校验与修稿路由

- 通用：`prompts.validate_daily_story_json`（字数、连说、单冲突等）。
- 类型扩展：`story_types.append_type_body_validation_errors`。
- 开场类型：`story_types.validate_type_opening`（传入 `type_code`）。
- 本地修稿：`prompts.try_local_patch_daily_story_body` 内调用
  `story_types.patch_type_body`。

解析类型：`parse_story_type_code`（`story_type` 或 `punchline_explain`）；
与选题不一致时以 punchline 为准。

### 5.1 硬卡边界（勿剧情穷举）

- **validate / patch**：只卡机读**不变量**（结构槽位、speaker、与类型契约一致的
  末段形态）；与 `*/quality.py` 共用抽象 pattern 时避免两套真理。
- **line / prompts / 重试 hint**：赛规措辞、反例、单主题创作约束（如更急赛规怎么写）。
- **禁止**：在 `validate.py` 为单篇剧情或词表写 regex（如某句禁用词）；
  「写得不好」走观感降分或改提示词，除非明确要求生成硬拦。
- Agent 细则：`.cursor/rules/daily-story-validate.mdc`。
